# シンプルに学ぶ宅建アプリ

宅地建物取引士試験のための一問一答（○×）アプリ。Flutter 製（iOS / Android / macOS / Web）。

## なぜ作るか

宅建アプリは既に飽和しています。ただし競っているのは**問題数**です（独学TODAY 3,484問、LEC 1,000肢など）。
一方、実際のユーザーの不満は問題数ではなく、ほぼ次の4点に集中しています。

| 既存アプリの不満 | このアプリの答え |
| --- | --- |
| 広告が邪魔で集中できない | 広告は**結果画面のみ**。出題中・解説中には絶対に出さない。買い切りで完全に消せる |
| 機能が多すぎて使いこなせない | 画面は3つ。出題モードの選択肢を持たない |
| アプリが落ちて学習データが消えた | 1問ごとにローカル保存。いつでも書き出せる |
| 通信環境で動画や問題が止まる | 学習は完全オフライン。問題データはアプリに同梱 |

「シンプル」をうたうアプリは多いものの、実際には出題モードの選択をユーザーに押し付けています。
このアプリは**設定を持たないこと自体を機能**として扱います。

### 広告についての方針

収益化のため広告を入れているが、**置いてよいのは結果画面だけ**。
競合の最大の不満が「広告が邪魔」であり、出題中や解説中に広告を出した時点でこのアプリの
存在理由が消える。バナーを増やしたくなったら、まずその前提を疑うこと。

この約束は `test/no_ads_during_study_test.dart` が構造的に検証している。
出題・解説・ホーム画面から広告ウィジェットを参照した時点でテストが落ちる。
インタースティシャル等の割り込み広告も同テストで禁じている。

配信は**常に非パーソナライズ広告**（`AdRequest(nonPersonalizedAds: true)`）。
これにより iOS の ATT ダイアログが不要になり、利用者を追跡せずに済む。
パーソナライズ広告に切り替えるなら、ATT の実装・EU の同意取得(UMP)・
`PrivacyInfo.xcprivacy`・`docs/privacy-policy.md`・App Store のプライバシー申告を
すべて揃えて更新する必要がある。

## 差別化の中心：配点比率に沿った出題

本試験は全50問で、内訳は 宅建業法20問 / 権利関係14問 / 法令上の制限8問 / 税その他8問。
つまり**宅建業法1問は税その他1問の2.5倍の価値がある**にもかかわらず、既存アプリはどの科目も等しく出題します。

このアプリは出題の重みを配点比率に直結させています（`lib/logic/scheduler.dart`）。
成績画面のバーの長さも配点比率に比例させ、「宅建業法が最重要」を見た目で理解できるようにしています。

得点表示も「正答率○%」ではなく、**本試験の配点で換算した予想得点（50点満点）**で出します。
合格ラインの目安（36点）まであと何点か、が一目で分かるほうが行動につながるためです。

### 予想得点は「未回答＝0点」で計算する

`predictedScore` は科目ごとの正答率をそのまま配点に掛けているわけではありません。
**未回答の問題を0点として分母に含めます**（`StudyController.predictedScore`）。

素直に「正答率 × 配点」にすると、宅建業法を1問正解しただけで正答率100%となり、
**20点取れる**と表示されてしまいます。学習者に誤った安心を与えるため、この方式は採りません。
現在の実装では 20点 × (1問 / 24問) = 0.8点 となり、解くほど実力に近づきます。

この挙動はテストで固定しています（`test/study_controller_test.dart` の
「1問正解しただけでは、その科目の配点を満額計上しない」）。「正答率×配点」に単純化しないこと。

## 出題ロジック

SM-2 を○×2値用に簡略化した間隔反復。ユーザーには一切設定させず、以下を自動で行います。

- 正解を重ねるごとに間隔を延長（1日 → 3日 → ease倍ずつ）
- 間違えたら連続正解をリセットし、10分後に再出題（同じセッション中に定着させる）
- 間違えるほど ease が下がり、その問題が頻繁に出る（下限1.3・上限2.8）
- 復習期限を過ぎた問題を優先。期限切れが長いほど優先度が上がる
- 全問が復習待ちでも「今日はやることがありません」で終わらせず、先取り演習を出す

## 構成

```
lib/
├── models/          Question, ReviewState, Category（配点比率を持つ）
├── logic/
│   ├── scheduler.dart        出題順と復習間隔（このアプリの頭脳）
│   └── study_controller.dart アプリ状態
├── data/            問題読み込み・学習データの保存/書き出し・広告・課金
└── ui/
    ├── screens/     ホーム・出題・結果・成績
    └── widgets/     結果画面のバナー広告
assets/questions.json  問題データ（300問）
icon/icon.svg          アプリアイコンの元データ
docs/                  プライバシーポリシー・App Store 提出メモ
```

状態管理は `InheritedNotifier` のみ。この規模でパッケージを足す理由がないため。

## 開発

```sh
flutter pub get
flutter test          # 全機能のテスト（72件）
flutter run
```

Web でも動きます（動作確認用。`flutter run -d chrome`）。
なお `flutter create` を再実行すると `test/widget_test.dart` が再生成され、
`MyApp` を参照して `flutter analyze` が落ちます。生成されたら削除してください。

アイコンを変えたら `icon/icon.svg` を編集して再生成:

```sh
rsvg-convert -w 1024 -h 1024 icon/icon.svg -o icon/icon.png
dart run flutter_launcher_icons
```

## 問題データの追加

`assets/questions.json` に追記するだけです。コード変更は不要。

```json
{
  "id": "gyo-025",
  "category": "宅建業法",
  "topic": "37条書面",
  "statement": "○×で答えられる断定文",
  "answer": true,
  "explanation": "理由と、正しい結論・数字を明示する",
  "reference": "宅建業法37条1項",
  "difficulty": 2
}
```

- `category` は `宅建業法` / `権利関係` / `法令上の制限` / `税その他` のいずれかと完全一致させること（`lib/models/question.dart` の `Category` と対応）
- `difficulty` は 1（基本）2（標準）3（応用）
- 科目ごとの問題数は本試験の配点比率（20 : 14 : 8 : 8）に近づけると出題が偏りません

## 問題データの品質

`assets/questions.json` に300問。科目別の内訳は本試験の配点比率と完全に一致させています
（宅建業法120 / 権利関係84 / 法令上の制限48 / 税その他48 = 20:14:8:8）。

`test/questions_data_test.dart` が機械的に検査できる範囲を自動で見ています。

- 科目の内訳が配点比率から外れていないか
- id・問題文の重複、必須項目の欠落
- **問題文に旧法令の表現**（瑕疵担保責任・錯誤無効・宅地造成等規制法）が残っていないか
- **毎年数値が変わる統計問題**が紛れていないか（同梱データなので翌年に誤りになる）
- 同一論点への偏り、○×の偏り

作成時は改正の反映（電子書面・相続登記義務化・改正民法・盛土規制法）を確認し、
確実性の低い論点（区分所有法の2026年改正、建築基準法の採光規定、変動の激しい税率の特例）は
意図的に出題から外しています。

> **重要**: 上記の自動検査は「機械的に分かる誤り」しか見つけられません。
> **法令解釈そのものの正しさは、リリース前に公式の問題集と突き合わせて確認してください。**
> 「解説の誤り」「旧法令のまま」は既存アプリが叩かれている急所であり、
> ここを外すとこのアプリの価値がなくなります。有料機能がある以上、責任も伴います。
