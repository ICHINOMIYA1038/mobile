# 次版1.0.4の準備：3問の後からプラン体験につなぐ

2026-11-11 更新。1.0.4・ビルド15向けに、解答後の案内を改善した。コードとテストは準備済み。App Store Connect へのアップロード・審査提出は未実施。

## 変えたこと

- 3問の結果の上部に、解答済みの問題数とプラン体験までの残り問数を出す。3問なら「あと7問」、10問に達したら体験へのボタンを出す。
- 続けて解くときは未回答の問題を開く。元の章に未回答がなければ、別の章から選ぶ。
- プラン体験は結果画面から直接開ける。条件を満たしていても、問題を続けることを選べる。
- 問題や分析の画面から戻ると、記録を取り直す。分析画面の「続けて問題を解く」も、全体の未回答を開き、戻ったら体験条件を更新する。
- 記録の取得に失敗したときは問数を推測しない。再取得と、未回答の問題への入口を残す。

結果画面は既存の home API を読み、`progress.seen` から問題数を表示する。同じ問題を繰り返した回数や正解数を、体験条件の問題数に足さない。体験の条件は従来どおり異なる10問で、実行時にもサーバーが確認する。

追加のイベントは `study_next_step_open`。`action` は `unanswered` または `preview`、`answered` は取得できた場合の問題数。学習者 ID と解答本文は含めない。アプリの版ごとに効果を確認する。

## 確認結果

- `flutter analyze --no-pub`：問題なし
- `flutter test --no-pub`：848件成功。うち新しい操作テストは7件
- `python3 scripts/check_insights.py`：問題なし
- 390×844の画面で、結果を開いた時点の「まだ解いていない問題を解く」が画面内にあることを確認

操作テストでは、9問から未回答の1問を解いて戻り、10問のプラン体験へ直接進む流れを確認した。分析から戻ったときの更新、通信の失敗、読み込み中の学習者の切り替え、古いサーバーでの表示も確認している。通信はテスト用に置き換え、本番の学習データ・AI・購入は使っていない。

この版の iOS ネイティブビルドとシミュレーターでの通し確認は未実施。既存の `build/ios/ipa/takken_talk.ipa` は提出済み1.0.3・ビルド14のため、1.0.4として再利用しない。
