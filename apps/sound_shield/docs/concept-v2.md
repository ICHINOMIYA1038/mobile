# Sound Shield v2 コンセプト — 「騒音計」から「部屋の防音診断」へ

作成: 2026-08-28。背景: iOS 1.0 が Guideline 4.3(a)（既存アプリとコンセプト類似）で却下。
目標: 月1万円の売上。方針: 技術で差別化し、クローンされにくく、払う人が明確なアプリにする。

---

## 1. なぜ今のコンセプトでは無理か

App Store JP を iTunes Search API で調査（2026-08-28）:

| 軸 | 状況 |
| --- | --- |
| 騒音計 / デシベル | デシベルX (18,963件★4.3) ほか1,000件超が数本。上位は10年選手。2026年だけで評価0件の新規が10本以上 |
| 騒音記録・証拠 | 2026年4〜8月に **評価0〜1件の「騒音ログ/証拠レポート」系が15本以上** 流入。全部無料。ここも既に飽和 |
| 音漏れ / 遮音 | 「防音チェッカー」(2026-07, 評価0, 買い切りPro) 1本のみ。**自分の音が外に漏れるか**を測る方向 |
| 内見 × 防音 | **アプリなし** |

Apple が 4.3 を出したのは、上の1〜2行目の群れの中に Sound Shield が見えたから。音源推定と改善提案は
「dBメーター + おまけ」の範囲に見えており、スクショ・メタデータも群れと区別がつかない。
**騒音計としての改良では抜けられない。測る対象と、払う人を変える。**

## 2. 新コンセプト

> **Sound Shield — 部屋の防音診断**
> 「どこから・何の音が・どれだけ入ってくるか」を可視化して、効く対策だけを選ぶ。

「今何dBか」ではなく「この部屋（or この物件）は騒音に対してどれだけ守られているか、どこが弱点か、
何をすれば何dB下がるか」に答える。既存の技術資産（リアルタイムdB・周波数帯別レベル・
SoundAnalysis音源推定・提案エンジン）はすべて部品として活きる。

### 払う人（優先順）

| # | ペルソナ | 課金の瞬間 | 需要の根拠 |
| --- | --- | --- | --- |
| P1 | **内見中の引越し検討者** | 内見当日、その場で「この部屋うるさい？」を知りたい | 「内見 壁の厚さ 確認」は HOME'S・防音専門店・地場不動産が軒並み記事化する定番テーマ。手法は「ノック」「手叩き」「スマホで音楽を流す」と全部アナログ。アプリ不在 |
| P2 | **騒音に悩んでいて対策グッズを買う直前の人** | 防音カーテン(数千〜数万円)・二重窓(十数万円)の購入前 | 防音カーテンは実測3〜5dB、低音には無効という情報が広く流通し「効果なかった」レビュー多数 → 「買う前に効くか知りたい」需要 |
| P3 | 在宅ワーカー・楽器演奏者（音漏れ側） | 会議・演奏前 | 競合1本あり。v2では後回し |

### 3つの中核機能（= 技術的な堀）

**A. 内見モード（3分ガイド診断）** — P1向け、最初にリリース
- ガイドに沿って順に計測: ①室内の暗騒音 ②窓を閉めた状態での外音の帯域分布 ③壁のノック音スペクトル
  （高く軽い響き=薄い壁、鈍い=重い壁。文献の経験則を周波数ピーク/減衰時間で数値化）
  ④手叩き残響（RT60簡易推定）⑤隣室・廊下側の音
- 出力: **防音スコア(0-100)** と弱点（窓/壁/ドア/床）、「この壁は木造〜軽量鉄骨相当 / RC相当」の推定、
  検出された音源（交通・工事・人の声…）
- **物件を保存して比較**（物件A vs B vs C）。内見は複数回るので比較表そのものが価値
- iPhoneマイクは未校正なので、絶対値でなく**同一端末の相対差**で評価する（競合と同じ考え方、正直に表示）

**B. 音の侵入マップ（AR）** — 差別化の本命、第2弾
- ARKit のワールドトラッキングで端末位置を取りながら壁・窓・ドア沿いに端末を動かし、位置×dB×帯域を
  記録 → 壁面上のヒートマップとして表示。「窓の右下から高音が、壁全面から低音が」が一目で分かる
- Flutter側は既存の Swift プラグイン(SoundMeterPlugin)を拡張し、ARSCNView を PlatformView で載せる
- これは**スクショ1枚でdBメーター群と別物**に見える。4.3対策としても最重要
- クローン困難: ARトラッキングと音響サンプリングの同期・端末の向きによるマイク指向性補正・
  位置ごとの暗騒音差し引きが必要で、テンプレアプリ勢は追随しづらい

**C. 対策シミュレーター（何をすれば何dB下がるか）** — P2向け
- 既存の suggestion_engine を「文章の提案」から「定量モデル」へ昇格
- 入力: 帯域別レベル + 音源種別 + 侵入経路（A/Bで判明）
- 各対策の帯域別減衰量を公開データから表にする（例: 防音カーテン 高域-3〜5dB/低域≈0、隙間テープ
  高域-2〜4dB、二重窓 -10〜15dB、防振ゴム 低域振動、吸音パネルは透過音には効かない…）
- 出力: 対策ごとの **予測ΔdB と費用**、コスパ順、**「この音には効きません」を明示**
  （防音カーテンで低音の交通音は下がらない、など。買って後悔を防ぐのが価値）
- **Before/After 検証**: 対策後に再計測 → 実測ΔdB を帯域別に表示。
  匿名の（対策種別・帯域・ΔdB）だけを集計してモデルを補正 → 使われるほど精度が上がるデータの堀

補助: 診断結果を PDF で書き出し（物件比較表 / 管理会社・大家への相談用）。「証拠」は前面に出さない
（飽和かつ4.3リスク）。

## 3. 収益設計

- **無料**: 現在の騒音計（ゲージ・3段階判定・音源推定・簡易提案）。ASOと信頼の入口
- **Pro 買い切り ¥980**（アプリ内課金・非消耗型）: 内見モードの保存/比較、ARマップ、シミュレーター、PDF
  - 買い切りにする理由: 内見・対策購入はスポット需要でサブスクが合わない。競合の「防音チェッカー」も買い切りPro
  - 「結果を見てから買う」: 診断1回分は無料で最後まで見せ、2件目の保存・比較・ARからPro
- 月1万円 = 手取り ¥833/本 × **12本/月**。ダウンロード転換率3%なら月400DL、
  「内見 防音」「壁 薄い」「防音カーテン 効果」系キーワードで取りにいく規模としては現実的

## 4. 4.3(a) への回答戦略

1. **1.0 のまま返信して粘らない。** 返信だけでは「dBメーター群」の印象は変わらない
2. v2（少なくとも A + C + Pro IAP）を実装し、**アプリ名/サブタイトル/スクショ/説明を全面刷新**して
   同じApp IDで再提出
   - サブタイトル案: 「部屋の防音診断・内見チェック」
   - スクショ1枚目: 内見スコア画面、2枚目: ARヒートマップ（第2弾なら対策シミュレーター）。
     **ゲージ画面は1枚目に置かない**
   - カテゴリ: ユーティリティ → ライフスタイル or 仕事効率化（騒音計群から離れる）
3. 再提出時の審査メモに「v1からコンセプトを変更し、部屋の遮音性診断・対策効果予測に特化した。
   計測はARKit位置追跡と帯域解析を組み合わせた独自実装で、汎用dBメーターとは目的が異なる」と明記

## 6. リスクと対処

- **物理精度**: 未校正マイク・機種差 → 同一端末の相対評価に徹し、スコアは順位付け用と明示。絶対dBの断定はしない
- **ARKit×Flutter の実装コスト** → フェーズ2に分離。フェーズ1だけでも4.3を抜けられる差別化にする
- **需要が「内見のときだけ」で薄い** → P2（対策購入前）と組み合わせて居住中も使える設計にする。
  ASOで「内見」「壁 薄い」「防音カーテン 効果」を押さえ、note/ブログで「内見で防音性を測る方法」記事を書いて流入を作る
- **競合「防音チェッカー」がこちらへ寄せてくる** → ARマップとBefore/Afterデータの蓄積で先行する

### オフライン検証（2026-08-28, `tool/impulse_lab`）
実機なしで解析ロジックを検証する CLI を追加。`ImpulseAnalyzer.swift` をアプリと共有(シンボリックリンク)。
- **合成音**（既知の RT60・中心周波数）: RT60 推定誤差は 0〜20%（10ms フレーム量子化で短い余韻ほど過大）。実用範囲
- **ESC-50 実録音**（木製ドアのノック30本・拍手30本, CC BY）:
  - 当初の「最初の0.6秒＝暗騒音」方式では冒頭から音が鳴るクリップで床が汚れ、検出 4/30。
    → **適応的な床推定**（直近1秒の下位20%パーセンタイル）＋「直近3チャンク最小値からの6dB以上の立ち上がり」に変更し **27/30**
  - ノックの重心中央値 ≈220Hz・低域比 0.7〜0.99・T20 0.05〜0.2s。「軽い壁＝高く響く」という当初の仮定は逆で、
    **中空パネルは低く長く共振する**。壁判定を「余韻の長さ＋低域共振」ベースに変更（`WallEstimate`: 余韻≥0.12s→軽い、
    低域比≥0.8かつ余韻≥0.06s→軽い、余韻<0.06sかつ非共振→重い）。ドア録音は light=16/medium=10/heavy=2
  - 未検出の拍手は連続したアプローズ（立ち上がりなし）。アプリは1回叩く前提なので問題なし
- 再実行: `cd tool/impulse_lab && swift run -c release impulse_lab synth` / `... wav data/esc50`（データは `.gitignore`、取得は README 参照）

### 実機で必ず検証すること
- 壁判定の閾値（`WallEstimate`: 余韻 0.06/0.12s、低域比 0.8）を RC・木造・軽量鉄骨の実物の壁で当てて調整する。
  ドア録音で方向性は確認済みだが、壁＋端末マイクでの絶対値は未検証
- 手叩き RT60 の妥当性（家具ありの部屋で 0.3〜0.6s 程度になるか）
- ARマップ: 球の間隔(8cm)・マイク位置オフセット(7cm)・トラッキング喪失時の挙動

### 実機フィードバック 1回目（2026-08-29）と対応
| 指摘 | 対応 |
| --- | --- |
| 物件名の入力が不安 | 任意項目に。「比較用のメモ、端末内にのみ保存」と明示。空欄なら「物件 n」 |
| 隣室側の壁を叩いても検出されない／大きく叩くのはマナー的に無理 | 検出チャンクを 1024→256 サンプル(約5ms)に細分化(短い衝撃音がRMSで薄まらない)、閾値 18→12dB。案内を「壁から30cm以内で軽く1回」に。ESC-50 ノック検出 27→30/30 |
| 市販の騒音計より約10dB低い | 表示オフセット 90→100 dB(AudioSpectrumAnalyzer / InstantLevelMeter / ImpulseAnalyzer 共通) |
| 対策の減衰量が適当に見える | 全対策に `evidence`(出典・実測条件)を追加して UI に表示。値を保守的に見直し(耳栓は NRR 実効値 10〜13dB、隙間テープ 1〜3dB、内窓は中高域10〜15dB/低域数dB など) |
